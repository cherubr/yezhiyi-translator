# 翻译请求与页面会话规则

规则版本：1；更新日期：2026-10-20；状态：当前分支实现，尚未发布。

这份文档用于讨论、开发和验收。系统规则仅在本开发文档中维护，设置页不再展示规则入口或弹窗；程序仍执行这些规则。请求频率与同时请求上限允许按服务配置。后续调整应同时修改代码、文档和对应回归，不能只改提示文字。

## 设置位置与术语

- 基本设置：选择默认服务、源语言和目标语言，提供“配置当前服务”入口；不再展示旧“并发数”。
- 翻译服务：分为“直接使用”（Google、MyMemory）和“自行配置”（百度、AI）。分组依据是是否需要填写连接信息，不承诺免费、无限额或所有网络可用。
- 服务详情 → 请求设置：选择“推荐配置”或“手动配置”，高级区域填写“每秒最多发送请求数”和“同时请求上限”，点击保存后生效。
- 每秒最多发送请求数（QPS）：真正启动的调用数，不是页面段落数。10 表示每秒最多启动 10 次；均匀发送，启动间隔至少向上取整的 1000÷10＝100 毫秒，同时检查滚动一秒窗口。
- 同时请求上限：已经发送、尚未结束的请求数量。QPS=10、同时上限=4 时，前四个请求都未结束就等待结果，不继续启动第五个；两项限制必须同时满足。
- 页面任务：待翻译的一个文字块。长任务可以拆成多个网络请求，缓存命中可以不发送请求；页面任务不是线程，也不等于网络请求。
- Unicode 字符：本模块按码点计数；UTF-8 字节：编码后的数据长度，例如常见汉字通常占 3 字节。两项预算先达到哪个就按哪个切分。

## 默认值与数据

唯一默认值来源：[core/request-policy.js](../core/request-policy.js) 的 DEFAULTS 和 LIMITS。以下是扩展的初始策略，**不是厂商承诺或账号额度探测结果**。服务方账号额度需自行核对，设置数值不会提升服务方实际额度；下表记录当前代码默认值。

| 服务 | 每秒最多发送 | 同时请求上限 | 单片字符预算 | 单片 UTF-8 字节预算 |
| --- | ---: | ---: | ---: | ---: |
| Google | 6 | 4 | 1200 | 1800 |
| 百度 | 6 | 4 | 900 | 2700 |
| MyMemory | 2 | 2 | 480 | 480 |
| AI（每个厂商独立保存） | 6 | 4 | 1200 | 1800 |

手动 QPS 接受 1～100 的整数，同时上限接受 1～32 的整数。非法表单值拒绝保存；异常存储值按对应默认值回退。推荐模式始终读取代码默认值。降低限制约束后续发送，不取消已发出的请求。恢复推荐只恢复该服务的请求参数，不清除凭据、不修改默认服务。

`chrome.storage.local.requestPolicies` 示例：

```json
{
  "baidu": {"mode": "manual", "qps": 10, "maxConcurrent": 4},
  "ai:deepseek": {"mode": "recommended", "qps": 6, "maxConcurrent": 4}
}
```

`requestPolicyVersion` 为 1。策略和本机凭据关联，保存在本机；普通语言与显示偏好仍同步。旧 `concurrency` 保留但不参与新调度，不把页面任务数擅自换算为 QPS。不存在新策略时自动采用推荐值；若发现同步区旧策略，迁移到本机，写入成功后再清理同步字段。

## 系统规则与验收

| 编号 | 当前规则 | 验收场景 |
| --- | --- | --- |
| TR-01 请求额度 | 后台统一排队；QPS、启动间隔和在途上限共同约束。排队与退避不占在途名额。页面最多同时提交 64 个文字任务；AI 当前视口的未完成整段数额外不超过该服务同时请求上限，完成一段再提交下一段，避免长段尾片被大量新段挤到队尾；滚动进入新视口有独立投递名额，仍受全页 64 段上限及后台账号额度约束。后台每个账号最多排队 512 个网络分片；超限返回可理解的错误，不无限增长。 | 同时提交多段，记录真实启动时刻和峰值，均不得越限；降低配置不打断在途请求。 |
| TR-02 服务隔离 | Google/MyMemory 分别共用调度；百度按 AppID；AI 按规范化地址和 Key，共享同账号不同模型额度。不同地址或账号分开。AI 厂商分别保存参数，别名指向同一账号时取已登记策略中的较低限制。 | 同账号跨页面/模型共同受限；不同 AI 地址可独立工作；切换厂商不覆盖另一家参数。 |
| TR-03 服务分块 | 页面提交完整文字，后台统一按字符与 UTF-8 双预算分块，尽量在词句边界切分；每段最多四个分片生产者，且不超过该服务同时上限。结果按原顺序拼接，任何分片失败都不伪装完整成功。单任务原文最多 100000 个 JS 字符单位。 | 汉字、英文、emoji 混排，切片拼回原文完整；单片不越预算；失败可保留成功片缓存供后续重试。 |
| TR-04 有限重试 | 网络、超时、HTTP 408/429/5xx 及已识别的临时服务错误最多尝试三次，**含首次**。凭据、权限、余额、格式或语言限制不盲目重试。每次重试重新走额度队列。每个请求响应头与正文共用 30 秒超时。 | 临时失败至多调用三次；凭据错误一次；取消不计失败；最终失败的缓存保留耗尽标记，不因滚动再开循环。 |
| TR-05 等待与保护 | 没有服务提示时，重试前等待 1 秒、2 秒，加 0～250 毫秒抖动；普通指数退避上限 30 秒。服务给出 Retry-After 时采用较长等待，不用普通上限截短。同账号其他排队任务共同等待，最后一次被限流也保持等待。连续三个最终失败触发 30 秒熔断，永久凭据/额度错误保持阻断，手动重试可重查。手动重试、离开/返回不清除提供方等待。 | 429 后加入新段仍需等待；离开再返回不能绕过等待；错误显示于面板及现有页面错误提示。 |
| TR-06 优先级与公平性 | Shift 与选中文字优先；其次最新视口任务；更早视口任务随后。同优先级在页面间交替领取名额，同一页的长段分片与其他段落也交替领取名额；没有其他段落等待时允许使用全部并发；优先级不能抢占已发出的请求，不能越过 QPS 或退避。 | 大页面排队时 Shift 领取下一个可用名额；旧视口不能一直挡住最新阅读位置。持续主动高优先级操作可能推迟普通任务。 |
| TR-07 离开暂停（方案 A） | 标签页不可见或窗口最小化后，收到可见性通知即停止该页新请求；在途结果允许完成并保留；返回继续未完成任务，不重发已完成内容。共享请求只要另一个消费者可见，仍可发送。未启动页返回不因返回本身启动（已启用自动启动的页面仍按该偏好处理）。 | 离开后发送计数不再增加，在途结果可增加；返回继续且保留重试次数/退避。可见性消息有异步延迟，不保证撤回已发出的调用。 |
| TR-08 取消隔离 | 用户取消恢复原文、清队列，并尝试取消仅本页需要的在途请求；其他页面共享消费者保留。取消后返回不重启整页；Shift 仍可翻译或还原单段，不解除整页取消。手动重新翻译才重新开启当前页会话。 | 取消后滚动、页面动态变化、离开返回均不补翻；Shift 单段仍正常。服务端已收到的请求可能继续处理或计费。 |
| TR-09 结果校验 | 页面代次、消息文档、请求批次和原文快照一起校验；切换引擎、配置、语言、节点复用或取消后，旧结果不能覆盖新页面。旧可见性版本不得恢复隐藏任务。 | 慢请求期间切换或修改原文，旧译文不能插入；刷新属于新文档，旧消费者取消。 |
| TR-10 缓存与生命周期 | 后台仅内存缓存，成功最多 256 条/10 分钟，失败 30 秒；相同内容、配置、模型及语言的在途请求合并。刷新清除页面译文与本页错误，但后台成功缓存及账号保护可能仍有效；MV3 后台退出后这些内存状态丢失，不承诺跨后台重启的持续限流。 | 同文跨页只发一次；一个消费者取消不影响另一个；不同目标语言不混用缓存。 |

AI 兼容接口没有统一的 Token 上限查询协议。当前是保守文本预算，**不做精确 Token 计算**，不自动探测每家账户的 RPM/TPM、日额度或上下文上限。服务报告超限后按错误处理，不承诺自动缩小分片或无限重试。若新增 Token 感知能力，应另立规则和验收。

## 网页翻译单元与采集规则

实现入口为 `core/translation-units.js`。本模块为独立编写的实现，参考公开产品的段落优先、区分排除/保留原文、保护文字后还原的设计思路，没有复制第三方扩展源码。

- 沉浸式翻译的[介绍](https://immersivetranslate.com/docs/)说明按段落保留上下文；[高级配置](https://immersivetranslate.com/en/docs/advanced/)分别定义排除、保持原文和块/行内规则。这不等于公开了其全部内部算法。
- TWP 的[公开实现](https://github.com/FilipePS/Traduzir-paginas-web/blob/master/src/contentScript/pageTranslator.js)展示了文字保护标记、翻译后还原及异常处理。不同服务对标记的兼容性需要实际验证，不能声称所有市场产品采用相同算法。

| 规则 | 实现与验收 |
| --- | --- |
| 单元识别 | 段落、标题、列表项及普通文字区域按语义/布局划分。正文中的行内链接、强调、span 与代码合并进同一单元。导航与控件保留紧凑展示。不能把含子段落的整列/整卡片合成一个任务。 |
| 连续区间 | 遇到输入、隐藏内容、独立代码块、图形或下级布局边界时结束当前文字区间。混合容器的连续文字、链接与行内代码归为同一区间，按实际节点覆盖去重；不读取输入控件的已填内容。 |
| 排除与保留 | 独立 pre/块级 code、编辑区域、隐藏内容跳过。可见行内 code、translate=no/.notranslate 内容只在本地保留映射，接口收到内部标记；纯代码/纯保护内容不发请求。 |
| 保护协议 | 标记形式为 `⟦YZY命名空间:序号⟧`，与原文发生碰撞时选用其他命名空间；按出现位置生成，允许译文重排，并兼容成对方括号/双方括号/中文括号、全角字符、空白及零宽分隔符；仅规范化标记内部，不改动译文正文。每个标记仍必须返回一次，禁止猜测缺失标记的位置。分块不能切断标记。丢失/重复/未知标记阻止插入，保留原文并提示；诊断只记录各类异常数量，不打印代码或响应正文，不新增自动请求循环。AI 提示词说明标记必须保留；机器翻译兼容性仍需实际服务测试。 |
| 展示与还原 | 正文译文放在完整原文之后独立成段；控件/导航采用紧凑样式。只移动/包装现有节点，接口结果以 textContent 展示，禁止把返回文本作为 HTML 执行；取消完整还原代码、链接、控件及事件。 |
| 状态归属 | 已请求/已完成段落的子链接/span 不重复提交。整页、Shift、动态补翻使用同一采集入口。局部内联变动归并到所属正文；返回时校验源节点位置、连续性、原文及任务代次，失效结果丢弃。 |
| 性能边界 | 本次扫描缓存元素样式和行内分析结果，布局边界提前停止下探；局部变动只扫描对应区域。请求预算和 QPS/并发保持由后台统一处理，不在采集器擅自提升限制。 |

一个翻译单元不等于一次物理请求：短段可只请求一次，长段仍按服务字符/字节预算分片。合并碎片能减少不必要的调用，但不能据此承诺所有 AI 服务的真实延迟已经恢复。

## 本地控制台耗时诊断

`core/constants.js` 的 `LOG_CONFIG` 在 development + debug 时开启详细耗时诊断；其他级别不创建后台诊断回调。重新加载扩展并刷新网页后，在网页 F12 → Console 中启用 Verbose/详细并筛选 `[页知译][诊断]`；后台控制台也保留同份阶段信息。正式打包强制 production + off，规则见 [日志配置](LOGGING.md)。

- `clientId` 是当前页面任务编号，`taskId` 是后台任务编号，`requestId` 是物理请求编号；相同请求共享时，多个页面任务可以对应同一个物理请求。
- `task_start` 显示文字字符数、UTF-8 字节数、分片数及本入口配置；没有原文或译文内容。
- `request_start.queueMs` 是当前一次尝试在后台额度队列中的等待时间，可能包含频率、并发、退避或不可见页面的等待；原因另见 `request_wait.reason`。重试会产生新的排队阶段。
- `configuredQps` / `configuredMaxConcurrent` 是当前入口配置；`qps` / `maxConcurrent` 是同账号合并后的真实上限，`policySources` 列出参与计算的入口与数值，不包含地址或 Key。`active` 是启动该请求时的账号在途总数，可能包括其他页面；它不是成功数。
- `request_success.executionMs` 是领取名额到执行器返回的耗时，包含接口前置检查及完整响应读取，不能直接等同于纯网络耗时。
- AI 的 `http_headers.headersMs` 为实际调用 fetch 到收到响应头的时间；`http_complete.httpMs` 为实际 HTTP 请求至完整 JSON 读取完成的时间，`bodyMs` 为响应头之后的读取时间。服务端缓冲生成时，生成耗时可能集中在收到响应头之前。这些数据不能拆解服务端内部的排队、推理和生成时间。
- `cache_hit` 不发送请求，`request_shared` 复用已有请求；共享请求的执行耗时属于底层物理请求。
- 页面“收到译文”的 `totalMs` 包含消息、配置准备、排队、重试和执行；“译文已显示”的 `insertMs` 记录返回后校验及插入耗时。后台分片可并行，各片耗时不能简单相加当作整段耗时。

诊断不改变请求数值、调度规则、接口 payload 或重试策略。只输出阶段、编号、入口标识、错误代码及统计数值，不输出原文、译文、密钥、模型配置、完整接口地址或内部缓存/账号键。

## 模块对应关系

1. `settings/settings.js`：服务分组、请求参数表单、保存/恢复及连接区域的默认服务选择；与控制面板共用 core/providers.js 的服务目录和就绪判断。
2. `core/request-policy.js`：默认值、范围校验、切片、账号作用域、结构化错误及响应超时。
3. `core/translation-runtime.js`：共享队列、频率/并发、优先级、缓存、消费者取消、退避和有限重试。
4. `background/service-worker.js`：读取配置、校验权限、页面身份、服务接口和服务错误映射。
5. `content/content.js`：可见文字识别、页面会话、可见性通知、Shift/选中优先级、过期结果校验和译文显示。

## 变更与验证要求

变更时标出影响的 TR 编号，修改单一默认值来源及文档表格，补对应行为用例；改变存储语义时升级规则版本并提供迁移。运行 `npm run check`、`npm test`、`npm run test:browser`。其中 `tests/request-policy.cjs` 验证真实调度行为；浏览器用本地接口检查页面与后台协作，不向付费服务发送测试请求。公开网络、真实额度和不同服务账号仍需人工验收。

本版不包含：主备切换、失败自动换引擎、多个短段合并请求、提前翻译下一屏、网站专用偏好、流式输出、持久化翻译缓存。

参考：[百度通用翻译 API](https://fanyi-api.baidu.com/doc/21)、[MyMemory 接口规范](https://mymemory.translated.net/doc/spec.php)。厂商规则变化时需核对当前文档与账号后台，不以本表替代厂商约束。
